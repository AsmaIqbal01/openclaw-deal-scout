# Implementation Plan: 006-web-dashboard

**Branch**: `006-web-dashboard` | **Date**: 2026-07-24 | **Spec**: [spec.md](spec.md)

---

## Summary

Add a self-contained web dashboard to the existing OpenClaw MCP gateway. The dashboard — a single vanilla HTML/CSS/JS file — is served at `http://127.0.0.1:18790/` via five new REST endpoints (`/api/*`) added to the gateway's Starlette app using FastMCP's custom route mechanism. The browser polls these endpoints every 60 seconds. No new Python dependencies, no build step, no external resources.

## Key Design Decisions

### 1. Custom Routes in FastMCP 3.4.4

FastMCP 3.4.4 exposes a `custom_route(path, methods)` decorator on the `FastMCP` instance. Routes registered this way are added to the underlying Starlette application alongside the `/mcp` endpoint. Registration happens in `server.py` using this pattern:

```python
from starlette.requests import Request
from starlette.responses import HTMLResponse, JSONResponse

@mcp.custom_route("/", methods=["GET"])
async def serve_dashboard(request: Request) -> HTMLResponse:
    ...

@mcp.custom_route("/api/status", methods=["GET"])
async def api_status(request: Request) -> JSONResponse:
    ...
```

If FastMCP 3.4.4's `custom_route` API differs from this signature, the fallback is to access `mcp.http_app()` and wrap with an additional Starlette `Router`.

### 2. REST Endpoint Implementations

All five handlers in `routes/api.py` call the same implementation functions already used by the MCP tools:

```python
from openclaw_gateway.tools.status import get_gateway_status, get_health
from openclaw_gateway.tools.pipeline import get_pipeline_cycles, get_deals, get_quota_usage, run_cycle as _run_cycle
import openclaw_gateway.server as _srv

async def api_status(request):
    return JSONResponse({
        "gateway": get_gateway_status(_srv._config),
        "health": get_health(_srv._config),
    })
```

Zero business logic duplication. The REST layer is purely transport.

### 3. Dashboard HTML File

`src/openclaw_gateway/static/dashboard.html` — a single file containing:
- Inline CSS (CSS custom properties for theming, system dark/light via `prefers-color-scheme`)
- Inline JS (ES6 modules not required; plain `<script>` is sufficient)
- No external dependencies (`<link>` to fonts, CDN scripts, or images)

The file is read at request time using:
```python
import importlib.resources as pkg_resources
html = pkg_resources.files("openclaw_gateway").joinpath("static/dashboard.html").read_text()
```

`pyproject.toml` must be updated to include the `static/` directory in the package:
```toml
[tool.setuptools.package-data]
"openclaw_gateway" = ["static/*"]
```

### 4. Dashboard UI Architecture

The dashboard JS fetches all five endpoints on load and on each 60-second interval using `Promise.all`:

```javascript
async function refresh() {
  const [status, cycles, deals, quota] = await Promise.all([
    fetchJSON('/api/status'),
    fetchJSON('/api/cycles?limit=20'),
    fetchJSON(`/api/deals?status=${currentFilter}&limit=50`),
    fetchJSON('/api/quota'),
  ]);
  renderStatus(status);
  renderCycles(cycles);
  renderDeals(deals);
  renderQuota(quota);
  updateTimestamp();
}
```

Run Cycle flow:
1. Click → disable button, show spinner, POST `/api/run-cycle`
2. `run_cycle` is synchronous server-side; `fetch()` blocks until done (up to ~10 min)
3. On resolve: render result banner, call `refresh()`, re-enable button
4. On 90s client timeout: show "still running — check pipeline.log" message, poll `/api/status` until `cycle_running` is false

### 5. CORS Headers

All `/api/*` handlers include `Access-Control-Allow-Origin: *` in their response. Handled via a shared response helper in `routes/api.py`.
